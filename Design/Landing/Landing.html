— 작동 방식 —

3단계로 합의된 답을 만듭니다.

한 모델의 환각, 한 모델의 편향, 한 모델의 사각지대 — HELIX는 토론으로 이를 상쇄합니다.

1

질문을 라우팅합니다

주제·복잡도·언어를 분석해, 강점이 다른 3~5개 모델을 자동으로 호출합니다.

routing → claude · gpt · gemini · deepseek
2

모델끼리 토론합니다

각 모델이 의견을 내고, 다른 모델의 답을 읽고 반박·동의·보완합니다. 최대 3라운드.

debate · 2~3 rounds · dissent surfaced
3

최종 답을 합성합니다

Lead 모델이 토론 전체를 읽고 단 하나의 답으로 통합 — 합의 점수와 함께 반환합니다.

synthesize · consensus score · cited
— 왜 한 모델만으론 부족한가 —

같은 질문, 세 가지 다른 답.

최신 벤치마크에서도 모델마다 정확도, 추론 스타일, 편향이 다릅니다. 중요한 결정에 한 모델만 쓰면 그 사각지대를 그대로 떠안게 됩니다.

POST https://api.helix.ai/v1/consensus
// 한 번의 호출, N개 모델의 합의
const r = await helix.consensus({
  prompt: "가격 전략을 짜줘",
  agents: ["claude", "gpt", "gemini"],
  rounds: 3,
  glass_box: true
});

console.log(r.answer);
console.log(r.consensus_score);  // 0.92
console.log(r.dissent);          // [{model, text}]

— FAQ —

자주 묻는 질문

여러 모델을 부른다면, 비용도 N배인가요?

아닙니다. Pro 플랜에는 월 300회의 합의 호출이 포함되며, 라우터가 자동으로 가벼운 모델 + 강한 Lead 모델 조합을 골라 평균 비용을 단일 GPT-4 호출의 1.4배 수준으로 유지합니다.

제 데이터로 모델을 학습시키나요?

아니요. 모든 플랜에서 사용자 데이터는 모델 학습에 사용되지 않습니다. Enterprise는 데이터 보관 0일 옵션과 자체 키(BYOK) 모드를 제공합니다.

모델이 의견 일치를 못 보면 어떻게 되나요?

합의 점수가 60% 미만이면 답을 강제로 통일하지 않고, "분기된 답 A / B" 형태로 양쪽 입장을 모두 보여드립니다. 결정은 항상 사용자 몫입니다.

API에서 어떤 모델을 쓸지 직접 지정할 수 있나요?

네. agents: ["claude-opus-4", "gpt-5", "deepseek-v3"] 형태로 직접 지정하거나, "auto"로 라우터에 위임할 수 있습니다.

오프라인/온프레미스 배포가 가능한가요?

Enterprise 플랜에서 AWS PrivateLink, Azure 전용 테넌트, 또는 자체 K8s 배포(Helm 차트)를 지원합니다. Llama 4 / Mistral 같은 오픈 모델로 풀리 폐쇄망 운영도 가능합니다.
